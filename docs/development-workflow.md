# 開発ワークフロー

1. Issueの目的、作業範囲、受け入れ基準、非目標を確認する。
2. `git fetch origin main` を実行し、最新の `origin/main` から `codex/<短い説明>` 形式のブランチを作成する。
3. `git status` で作業ツリーを確認し、Issueに必要な最小範囲だけを変更する。
4. 仕様書を更新または追加し、実装と検証方法を先に明文化する。
5. 実装を行い、変更に対応する検証を実行する。実機が必要で未実施の場合は、その事実と理由を記録する。
6. 差分、リンク、READMEとの整合性、秘密情報の混入を確認する。
7. 目的が分かるコミットを作成し、作業ブランチをoriginへpushする。
8. `main` 向けPRを作成する。PRテンプレートを埋め、本文に `Closes #番号` を含める。
9. 人間レビューで仕様・リスク・未検証事項を確認し、承認後にのみマージする。

## 最小限のチェック

実装コードがない変更では、Markdownの構文確認、相対リンクの存在確認、`git diff --check`、差分レビューを行う。実装や依存関係が追加された場合は、その変更に対応するテスト・型チェック・lintを追加で実施する。CIは必要なチェックが明確になってから最小限構成する。
